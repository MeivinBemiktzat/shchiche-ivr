# מערכת IVR עבור shchiche.com (ימות המשיח + Vercel)

## מבנה הפרויקט (4 קבצי קוד עיקריים)

1. `api/ivr.js` — נקודת הכניסה הראשית (`api_link`). מנהלת את כל שלבי השיחה.
2. `lib/wp.js` — משיכת שאלות מ-shchiche.com דרך ה-endpoint הפרטי `shc-reader/v1/questions` (ראה `הוראות_לטכנאי.md`) + קאש בזיכרון (מתרענן כל שעה).
3. `lib/yemot.js` — בניית תשובות בפרוטוקול הטקסטואלי של ימות (`read=`, `id_list_message=` וכו').
4. `api/transcribe.py` — פונקציית Python נפרדת שמתמללת הקלטות עם `SpeechRecognition` מול Google.

קובץ עזר נוסף: `lib/yemotApi.js` — קליינט ל-Management API של ימות (הורדת קבצי הקלטה).

## פריסה (Deploy) ל-Vercel דרך GitHub

1. דחפו את התיקייה הזו לריפו ב-GitHub.
2. ב-Vercel: New Project → Import מה-GitHub repo.
3. Vercel מזהה אוטומטית גם את `api/ivr.js` (Node) וגם את `api/transcribe.py` (Python) כ-Serverless Functions נפרדות.
4. הגדירו את משתני הסביבה (Environment Variables) בהגדרות הפרויקט ב-Vercel:

| משתנה | תיאור |
|---|---|
| `WP_READER_USERNAME` | `username` מתוך `connection.json` (`shc_posts_reader`) |
| `WP_READER_APP_PASSWORD` | `application_password` מתוך `connection.json` — שמרו בסוד, אל תחשפו בקוד |
| `WP_QUESTIONS_ENDPOINT` | אופציונלי, ברירת מחדל `https://shchiche.com/wp-json/shc-reader/v1/questions` |
| `YEMOT_API_KEY` | טוקן ה-Management API של ימות (להורדת קובץ ההקלטה בחיפוש קולי) — מומלץ על פני השיטה הישנה |
| `YEMOT_SYSTEM` / `YEMOT_PASSWORD` | חלופה ישנה יותר ל-`YEMOT_API_KEY`, נשארת לתאימות לאחור בלבד |
| `TRANSCRIBE_URL` | כתובת מלאה לפונקציית התמלול, לדוגמה `https://your-project.vercel.app/api/transcribe` |

⚠️ **חשוב**: `WP_READER_APP_PASSWORD` היא סיסמת אפליקציה מוגבלת (קריאה בלבד, סוג תוכן `question` בלבד) — לא סיסמת הניהול הרגילה של האתר. אין לשים אותה בקוד, רק במשתני הסביבה של Vercel. אם צריך לבטל גישה, בעל האתר מוחק את הסיסמה הזו דרך `wp-admin` (ראה `הוראות_לטכנאי.md`).

5. אחרי הפריסה תקבלו כתובת כמו: `https://your-project.vercel.app/api/ivr`

## הגדרת השלוחה בימות המשיח

בקובץ `ext.ini` של השלוחה הרלוונטית:

```ini
type=api
api_link=https://your-project.vercel.app/api/ivr
api_url_post=yes
api_wait_answer_music_on_hold=yes
```

`api_wait_answer_music_on_hold=yes` חשוב במיוחד עבור חיפוש קולי — כי הורדת ההקלטה + התמלול מול גוגל לוקחים כמה שניות, וזה מונע שקט מוזר בשיחה.

### חשוב לגבי ההקלטה (חיפוש קולי)

בקוד (`api/ivr.js`) מוגדר ש-Yemot תשמור את ההקלטה בתיקייה `/9` בשלוחה עם שם קובץ `SearchRec`, עד 20 שניות. ודאו שתיקייה `9` קיימת תחת השלוחה, או שנו את הנתיב לפי הצורך.

## איך זה עובד (זרימה)

1. כניסה → תפריט: הקישו 1 לחיפוש קולי, 2 לשמיעת השאלות האחרונות שנוספו לאתר.
2. **נתיב חיפוש קולי**: הקלטה → הורדת הקובץ מימות → שליחה ל-`api/transcribe.py` → תמלול מול Google → חיפוש טקסטואלי (fuzzy) על כלל השאלות מהקאש → הקראת התוצאה המתאימה ביותר.
3. **נתיב "אחרונים"**: הקראת עד 9 השאלות האחרונות (ממוינות לפי מספר שאלה יורד) → בחירה בהקשה → הקראת התשובה המלאה (TTS).

## אין קטגוריות — למה?

ה-endpoint הפרטי (`shc-reader/v1/questions`) מחזיר רק `id`, `title_raw`, `content_raw` — בלי קטגוריה, תגית, תאריך פרסום או קישור (ראה `הוראות_לטכנאי.md`). לכן אין דרך לבנות ניווט אמיתי לפי קטגוריה מול המקור הזה, וה-IVR מסתמך רק על חיפוש טקסטואלי ועל "אחרונים" (מיון לפי `id`, שמשמש קירוב סביר לתאריך פרסום). אם בעתיד ירצו ניווט לפי קטגוריה, יש לבקש מבעל האתר endpoint נוסף שחושף אותה.

## מגבלות ידועות שכדאי לדעת

- **Google Web Speech API (ללא מפתח)**: זהו שירות לא רשמי בחינם עם הגבלת קצב שימוש. לעומס גבוה (הרבה שיחות בו-זמנית) מומלץ לעבור בעתיד ל-Google Cloud Speech-to-Text עם מפתח API בתשלום.
- **תפריט "אחרונים" מוגבל ל-9 פריטים** (הקשה 1-9) — אם ירצו יותר, אפשר בהמשך להוסיף "עמוד הבא" (הקשה 0).
- **קאש בזיכרון**: מתאפס בכל "cold start" של הפונקציה. אם רוצים קאש עמיד יותר בין קריאות, אפשר להוסיף Vercel KV או Redis בהמשך.
- **`content_raw` הוא תוכן גולמי** (לא HTML מעובד — כולל shortcodes/קיצורים כפי שנשמרו במקור). `lib/wp.js` מנקה shortcodes בסגנון `[...]` וסימני HTML בצורה כללית; אם יתגלה תוכן שלא מוקרא טוב, כדאי לבדוק דוגמאות אמיתיות מהקאש ולחדד את `cleanRawText`.
- **שאיבה מרוכזת עלולה להיחסם (418)**: לפי `הוראות_לטכנאי.md` התקבלה תשובת 418 בבדיקת רשת עם שאיבה מרוכזת. `lib/wp.js` שולף עמוד אחר עמוד ברצף (לא במקביל) בדיוק מהסיבה הזו — אין לשנות זאת ללא תיאום מול בעל האתר.
